# Cloudflare R2 Dual-Bucket Complete Setup Guide (Investra)

This guide provides end-to-end instructions for creating and configuring the Cloudflare R2 storage buckets for the Investra platform.

---

## 1. Storage Architecture Overview

Investra uses a **Dual-Bucket Strategy** to physically isolate public media assets from confidential documents:

```
[ Frontend Browser ]
       │
       │ 1. Request Presigned PUT URL
       ▼
[ NestJS Backend ] ──(Generates Presigned S3 URL)──────────────┐
       ▲                                                       │
       │ 2. Returns Presigned URL                              │
       │                                                       ▼
[ Frontend Browser ] ──3. Direct PUT Upload──────────> [ Cloudflare R2 ]
       │                                              ├── Public Bucket (Avatars, Covers, Videos)
       │ 4. Confirm Upload with mediaId                └── Private Bucket (KYC Docs, Pitch Decks)
       ▼
[ NestJS Backend ] ──(HeadObject Verification)────────> Marked as UPLOADED in Database
```

| Bucket | Access Level | Stored Assets | Access Strategy |
| :--- | :--- | :--- | :--- |
| **`investra-media-public`** | **Public** | User Avatars, Campaign Covers, Pitch Galleries, Public Videos | Served directly to browsers via Cloudflare CDN / `r2.dev` public URL |
| **`investra-media-private`** | **Private** | KYC Documents (NIDs, Passports), Confidential Pitch Decks, Financial Reports | **Public access disabled**. Access granted exclusively through 15-minute Presigned GET URLs generated by NestJS for authorized users |

## 2. Cloudflare Dashboard: Step-by-Step Bucket Creation

Follow these exact steps in your Cloudflare Console (**R2 Storage** -> **Create bucket**):

### Bucket 1: `investra-media-public`

1. **Bucket Name:**
   - Enter: `investra-media-public`
   - *(Note: Use all lowercase letters and hyphens)*

2. **Location Hint (Optional):**
   - **Select:** **`Automatic`** (or **`Asia Pacific (APAC)`**)
   - **Why:** Cloudflare auto-detects your nearest region. Selecting `Automatic` or `Asia Pacific (APAC)` ensures the lowest latency and fastest upload/download speeds for users in Bangladesh and South Asia.

3. **Specify Jurisdiction:**
   - **Select:** **`None` (Leave unchecked / empty)**
   - **Why:** Jurisdictions (e.g. EU or FedRAMP) are for specific legal data-residency compliance. Investra does not require regional locking, so leave it unrestricted.

4. **Default Storage Class:**
   - **Select:** **`Standard`**
   - **Why:**
     - **Standard:** Designed for assets accessed regularly. Has **zero retrieval fees**. Public media like profile pictures, campaign covers, and videos are frequently accessed by visitors, so `Standard` is required.
     - **Infrequent Access:** Designed for archival data and backups. Charges data retrieval fees upon access. **Do NOT select this.**

5. Click **Create bucket**.

---

### Bucket 2: `investra-media-private`

1. Return to the R2 Storage overview page and click **Create bucket**.

2. **Bucket Name:**
   - Enter: `investra-media-private`

3. **Location Hint (Optional):**
   - **Select:** **`Automatic`** (or **`Asia Pacific (APAC)`**)

4. **Specify Jurisdiction:**
   - **Select:** **`None` (Leave unchecked / empty)**

5. **Default Storage Class:**
   - **Select:** **`Standard`**
   - **Why:** Ensures fast access to KYC documents and pitch decks without incurring retrieval charges when administrators or investors inspect them.

6. Click **Create bucket**.

## 3. Post-Creation Bucket Configuration

### Step A: Public Access Setting

#### 1. Public Bucket (`investra-media-public`)
- Go to **R2 Storage** -> Click **`investra-media-public`** -> Go to the **Settings** tab.
- Scroll down to the **Public Access** section:
  - **Option 1 (Recommended for quick testing / free):**
    - Under **R2.dev Subdomain**, click **Allow Access**.
    - Type `allow` into the confirmation modal and click **Allow**.
    - Copy the generated URL (e.g., `https://pub-xxxxxxxxxxxxxxxx.r2.dev`).
  - **Option 2 (Production Custom Domain):**
    - Under **Custom Domains**, click **Connect Domain** and add your subdomain (e.g., `cdn.investra.com` or `media.investra.com`).

#### 2. Private Bucket (`investra-media-private`)
- Go to **R2 Storage** -> Click **`investra-media-private`** -> Go to the **Settings** tab.
- Scroll down to **Public Access**:
  - **Keep Public Access DISABLED** (Do not enable `r2.dev` subdomain and do not connect a custom domain).
  - ⚠️ **Security Warning:** This bucket holds sensitive government IDs, passport scans, and confidential pitch decks. It must remain private.

---

### Step B: CORS (Cross-Origin Resource Sharing) Setup

Because the frontend browser uploads files directly to Cloudflare R2 using HTTP PUT (via presigned URLs), **both buckets must have a CORS policy configured**.

For **both** `investra-media-public` and `investra-media-private`:
1. Open the bucket -> Click the **Settings** tab.
2. Scroll to the **CORS Policy** section -> Click **Add CORS Policy**.
3. Paste the following JSON:

```json
[
  {
    "AllowedOrigins": [
      "http://localhost:3000",
      "http://localhost:3001",
      "https://investra.vercel.app",
      "https://investra-frontend-4m5v.onrender.com"
    ],
    "AllowedMethods": [
      "GET",
      "PUT",
      "HEAD"
    ],
    "AllowedHeaders": [
      "*"
    ],
    "ExposeHeaders": [
      "ETag"
    ],
    "MaxAgeSeconds": 3600
  }
]
```
4. Click **Save**.

## 4. Generate R2 API Tokens for the Backend

The NestJS backend requires S3-compatible credentials to issue presigned URLs, verify uploads with `HeadObject`, and delete files.

1. In the Cloudflare Dashboard, go to **R2 Storage** (the main overview page).
2. On the right-hand sidebar, click **Manage R2 API Tokens**.
3. Click **Create API Token**.
4. Configure the token:
   - **Token Name:** `investra-backend-token`
   - **Permissions:** Select **Object Read & Write** (Allows the backend full read, write, and delete capabilities).
   - **Specify bucket(s):** Choose **All buckets** (or select both `investra-media-public` and `investra-media-private`).
   - **TTL:** Leave as default or choose indefinite.
5. Click **Create API Token**.
6. Immediately copy the credentials displayed:
   - **Account ID** (available on the R2 overview page sidebar).
   - **Access Key ID**
   - **Secret Access Key**
   - **Endpoint for S3 clients:** `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`

## 5. Configure Backend Environment (`backend/.env`)

Add or update the following variables in your `backend/.env` file:

```env
# Cloudflare R2 Credentials
R2_ACCOUNT_ID=your-cloudflare-account-id
R2_ACCESS_KEY_ID=your-r2-access-key-id
R2_SECRET_ACCESS_KEY=your-r2-secret-access-key
R2_ENDPOINT=https://your-cloudflare-account-id.r2.cloudflarestorage.com

# Bucket Names
R2_PUBLIC_BUCKET_NAME=investra-media-public
R2_PRIVATE_BUCKET_NAME=investra-media-private

# Public Base URL (r2.dev URL or custom domain without trailing slash)
R2_PUBLIC_URL=https://pub-xxxxxxxxxxxxxxxx.r2.dev
```

## 6. Quick Selection Reference

| Cloudflare Field | Value to Select | Rationale |
| :--- | :--- | :--- |
| **Bucket 1 Name** | `investra-media-public` | Standardized naming matched to backend policies |
| **Bucket 2 Name** | `investra-media-private` | Standardized naming matched to backend policies |
| **Location Hint** | `Automatic` or `Asia Pacific (APAC)` | Low latency for users in Bangladesh & South Asia |
| **Specify Jurisdiction** | `None` (Unchecked) | No arbitrary regional restrictions needed |
| **Default Storage Class** | `Standard` | No retrieval fees; lowest latency for active assets |
| **Public Bucket Access** | Enable `r2.dev` or Custom Domain | Required so browsers can display images/videos |
| **Private Bucket Access** | Keep `Disabled` | Required to secure KYC documents & pitch decks |
| **CORS Policy** | Apply JSON to **both** buckets | Enables direct browser PUT uploads via presigned URLs |
| **API Token Permissions** | `Object Read & Write` | Grants NestJS S3 client full read, write, and head permissions |
