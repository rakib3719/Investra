## Why

Investra requires an enterprise-grade, scalable, and cost-effective media and file storage infrastructure for handling user profile avatars, startup campaign covers, pitch galleries, pitch decks (PDFs), financial audits, founder/investor KYC verification documents, and pitch videos. Directly uploading or streaming multi-megabyte binary files through the NestJS backend exhausts server memory, blocks event loops, and causes excessive bandwidth costs.

By leveraging Cloudflare R2 (S3-compatible object storage) with two segregated buckets (Public and Private), zero egress fees, and a direct-to-storage presigned URL architecture, Investra achieves zero backend binary load, high security for confidential documents, and clean lifecycle management for all uploaded media.

## What Changes

- **Two Separate Cloudflare R2 Buckets:**
  - **Public Bucket:** Houses public marketplace assets (`AVATAR`, `CAMPAIGN_COVER`, `CAMPAIGN_GALLERY`). Derived as `R2_PUBLIC_URL + "/" + key` (supporting free `r2.dev` subdomains or future custom CDN domains without DB migration). Loaded directly by browser; NestJS never proxies binaries.
  - **Private Bucket:** Houses confidential assets (`KYC_DOCUMENT`, `CONFIDENTIAL_PITCH_DECK`, `FINANCIAL_REPORT`). No public URL. Accessed strictly via temporary, 15-minute Presigned GET URLs generated by NestJS after checking DB metadata and business authorization rules. Browser downloads directly from R2; NestJS never proxies binaries.
- **Five-State Media Lifecycle:**
  - `PENDING_UPLOAD` → `UPLOADED` → `ACTIVE` → `DELETE_PENDING` → `DELETED`.
  - `POST /api/v1/media/confirm-upload` transitions files from `PENDING_UPLOAD` to `UPLOADED` upon verifying object presence and size via R2 `HeadObject`. It does **not** mark them `ACTIVE`.
  - `ACTIVE` status is only assigned when the parent business entity (User Profile, Campaign, KYC submission) is successfully saved.
- **Safe Media Replacement:**
  - When replacing existing active media (e.g., avatar), new media is set to `UPLOADED`. The old media remains `ACTIVE` until database transaction commits. Upon commit, new media becomes `ACTIVE`, old media transitions to `DELETE_PENDING` and is deleted from R2. If database commit fails, old media remains safe and `ACTIVE`.
- **Explicit Media Deletion:**
  - `DELETE /api/v1/media/:id` allows authenticated owners to delete uncommitted `UPLOADED` media or remove active media, cleaning up R2 storage.
- **Orphan Cleanup Strategy:**
  - Documented free-hosting-compatible cleanup strategy (idempotent maintenance endpoint/job + R2 lifecycle rules) to purge stale `PENDING_UPLOAD` and unattached `UPLOADED` records older than 24 hours, even if the NestJS instance sleeps on Render Free tier.
- **Video Strategy:**
  - Direct short video uploads (< 100MB) to R2 and external video presentation links (YouTube/Vimeo) with server-side URL validation.
- **Reusable Frontend Components:**
  - Next.js upload dropzone utilizing `XMLHttpRequest` for reliable upload progress tracking, upload cancellation via `abort()`, image/PDF previews, remove action, and retry states.

## Impact

- **Backend (`backend/`):**
  - Environment variables: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_ENDPOINT`, `R2_PUBLIC_BUCKET_NAME`, `R2_PRIVATE_BUCKET_NAME`, `R2_PUBLIC_URL`.
  - Prisma schema: Updated `MediaFile` entity with 5-state status enum, lifecycle timestamps (`activatedAt`, `deletedAt`), and entity relations (`User.avatarMediaId`, `Campaign.coverMediaId`, `Campaign.pitchDeckMediaId`, etc.).
  - New `MediaModule` implementing `R2StorageService`, `MediaService`, and `MediaController`.
- **Frontend (`frontend/`):**
  - Reusable upload widgets (`FileUploadDropzone`, `FilePreview`, `PdfViewerModal`) with direct R2 upload progress and cancel/remove support.
- **Security & Storage:**
  - Cloudflare R2 CORS configuration restricting access to configured frontend origins.
  - Strict server-side category policy mapping each category to public or private bucket, max file sizes, and allowed MIME types.
